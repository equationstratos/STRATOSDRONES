A drone, fully in the open

The DJI Tello EDU is a brilliant learning platform — but it's a closed box. STRATOSDRONE keeps everything that made it great (the size, the SDK, the swarming) and opens all of it: schematic, PCB, CAD, firmware and a simulator, under permissive licenses.

01Same protocol

Speaks Tello SDK 2.0 on the wire — UDP 8889/8890/11111. Existing djitellopy scripts run unmodified, including the video stream.

02Simulate first

A full Gazebo Harmonic model runs the exact same fc_core flight code as the firmware. Fly the mission in sim, then on hardware — no rewrite.

03Actually buildable

KiCad board with a JLCPCB assembly package, OpenSCAD airframe → STL, and an ESP-IDF firmware tree. Nothing is hand-waved.

Specs vs DJI Tello EDU

Same flight envelope and Tello-compatible props, with a modern open brain: an ESP32-P4 doing flight + a hardware H.264 camera pipeline, paired with an ESP32-C6 for Wi-Fi 6.

Designed to look and load like the original

A close, printable read of the real Tello: double struts splay from each body corner to the motor pods instead of a single arm, the canopy is a smooth clip-on shell with a clean camera nose, and the 1S pack loads from the rear — just like the drone it's modelled on.

Double-strut arms

Two solid struts per motor, splayed from the body to each pod — the same twin-arm silhouette as the reference Tello, seen from every angle. A arm_lattice switch opens them into a triangulated truss if you'd rather print it lighter.

Rear-loading battery, on top of the board

The pack slides in from the back over a honeycomb-vented floor and rides on top of the mainboard — it can't slide under and block the downward ToF / optical-flow sensors. No need to pull the canopy to swap a battery.

Real Tello prop guards clip straight on

Each motor pod carries a clip collar sized to the actual DJI Tello guard's C-clip — the same guards from a real Tello (or a spare set) snap on directly, ring concentric with the prop, clip on the nacelle. No adapter part to print or design.

Drop-in fit

Sized straight from the real guard's geometry — no redesign, no printed adapter. Clip them on, clip them off.

One printed pair

Just body_bottom_v2.stl + body_top_v2.stl — two parts, no supports beyond the motor pods, ≈23 g in PLA.

Sensors stay clear

A honeycomb-vented floor with two dedicated apertures keeps the downward ToF and optical-flow sensors looking straight through — nothing printed in their field of view.

How it's built

Five layers, one repository — each independently buildable and tested in CI.

◆fc_core — flight control

A platform-independent C99 core (no RTOS deps) compiled into both the ESP32-P4 firmware and the Gazebo plugin. Same code, same behaviour, in sim and in the air — with host-side closed-loop SIL tests.

◆Hardware — KiCad PCB

A compact 38×74 mm, double-sided mainboard generated from a single design database (design.py → board, BOM, CPL, pinmap). ESP32-P4 + C6, MOSFET motor drivers, full IMU/baro/ToF/flow sensor suite.

◆CAD — Tello-look airframe

OpenSCAD double-strut frame and clip-on capot → STL. Rear battery bay riding on top of the board, press-fit 8520 pockets and clip collars for real Tello prop guards — all from shared parameters.

◆Sim + SDK

Gazebo Harmonic twin with a Tello-protocol UDP endpoint and multi-drone swarms, plus stratospy — a thin add-on over djitellopy for the STRATOS extensions.

One board, everything on it

A compact 38×74 mm, double-sided mainboard generated straight from design.py — ESP32-P4 flight MCU with a hardware H.264 pipeline, an ESP32-C6 for Wi-Fi 6, and the full IMU / barometer / ToF / optical-flow sensor suite, all courtyard-checked so nothing overlaps.

Every reference, mapped

A generated component map labels every part on both sides of the board so you can place and inspect it with confidence before ordering.

Top — MCU, RF, motor drivers

ESP32-P4 + C6 down the spine, motor FETs in the corners, USB-C on the edge. Four copper planes poured (GND ×2, 3V3, VBAT).

Bottom — the sensor side

ToF + optical-flow looking straight down through a dedicated aperture in the VBAT pour, clear of copper.

Placement is done and clean; the bulk of the signal routing is done too (AI-assisted, then hand-finished), with ~106 connections left — see hardware/pcb/KNOWN_GAPS.md for the exact list before you order.

Build your own

Everything you need is in the repository. The short version:

  1. Simulate it first. Build the Gazebo plugin, spawn a drone, and run python sdk/python/examples/01_hover.py — takeoff, hover, land, over the Tello protocol. No hardware required.
  2. Finish routing, then order. Open the KiCad project, close out the remaining ratsnest (KNOWN_GAPS.md lists exactly what's left), fill zones, and send the JLCPCB gerbers/BOM/CPL package off for assembly. Cross-check against the component map first.
  3. Print the airframe. Slice body_bottom_v2.stl + body_top_v2.stl in PETG or tough PLA — light supports only under the motor pods.
  4. Assemble. Press in the 8520 motors, mount the board on the M2 bosses, route the motor wires along the arms, slide the 1S pack in from the rear, clip on the capot, clip on the prop guards.
  5. Flash & fly. Build the ESP-IDF firmware for the ESP32-P4, flash, and connect — your simulated mission scripts now run on the real drone, unchanged.

⚠️ This is a flying machine with spinning props. Read docs/safety.md before the first flight — guards on, props off for the first power-up, proper LiPo handling.
